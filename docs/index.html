uTwin OpenSDK Java 是面向 uTwin 具身智能中枢 Open API 的 Java 8+ 客户端。SDK 封装 AccessKey/SecretKey 签名、Token 获取和刷新、HTTP 连接池、错误处理、重试策略和分页遍历，业务代码只需要构建请求对象并调用对应服务客户端。

当前版本覆盖 /api/open/v1 下的机器人、地图、拓扑路径、导航路径、讲解、动作等接口。SDK 不依赖 Spring，可在普通 Java、Spring Boot、批处理任务和集成平台中使用。

1. SDK 概述

SDK 由核心能力和服务客户端组成：

  • 核心能力：认证、Token 管理、HTTP 传输、JSON 映射、异常和分页基础模型。

  • 服务客户端：机器人、地图、路径、讲解和动作相关接口封装。

核心调用流程为：构建 UTwinClient，选择领域客户端，构建 Request，调用接口并读取 Response。SDK 会在请求前自动获取 Token，并在 Token 过期或服务返回 401 时刷新后重试一次。

2. 环境要求

  • JDK 8 或更高版本。

  • Maven 3.8 或更高版本。

  • 可访问 uTwin 具身智能中枢 Open API 服务端地址。

  • 已开通的 AccessKey 和 SecretKey。

SDK 使用 Apache HttpClient 5、Jackson 和 SLF4J，不需要 Spring 容器。

3. 安装

在应用中引入 services 依赖即可获得完整客户端能力：

<dependency>
    <groupId>com.bwton.utwin</groupId>
    <artifactId>utwin-opensdk-services</artifactId>
    <version>3.2.0</version>
</dependency>

如仅需认证、HTTP 或基础模型，可单独引入 core 依赖：

<dependency>
    <groupId>com.bwton.utwin</groupId>
    <artifactId>utwin-opensdk-core</artifactId>
    <version>3.2.0</version>
</dependency>

4. 凭证配置

AccessKey 和 SecretKey 用于生成签名并换取 JWT Token。推荐在生产环境通过环境变量注入：

export UTWIN_ACCESS_KEY=your-access-key
export UTWIN_SECRET_KEY=your-secret-key

Java 代码中使用 EnvironmentCredentialsProvider：

UTwinClient client = UTwinClient.builder()
    .endpoint("https://utwin.example.com")
    .credentialsProvider(EnvironmentCredentialsProvider.create())
    .build();

本地调试或命令行工具也可以使用静态凭证：

StaticCredentialsProvider.create(
    AccessKeyCredentials.of("your-access-key", "your-secret-key"));

5. 第一个请求

try (UTwinClient client = UTwinClient.builder()
        .endpoint("https://utwin.example.com")
        .credentialsProvider(StaticCredentialsProvider.create(
            AccessKeyCredentials.of("your-access-key", "your-secret-key")))
        .build()) {

    ListRobotsResponse response = client.robot().listRobots(
        ListRobotsRequest.builder()
            .pageNum(1)
            .pageSize(20)
            .build());

    for (RobotItem robot : response.data()) {
        System.out.println(robot.name());
    }
}

UTwinClient 实现 AutoCloseable，建议按应用生命周期复用，并在应用退出时关闭。

6. Hello Robot

机器人领域入口为 client.robot()，常见操作包括查询列表、查询运行态、下发指令和查询任务结果。

GetRobotRuntimeResponse runtime = client.robot().getRobotRuntime(
    GetRobotRuntimeRequest.builder()
        .robotId("robot-sn")
        .build());

SendCommandResponse command = client.robot().sendCommand(
    SendCommandRequest.builder()
        .robotId("robot-sn")
        .type(1)
        .messagesType("robot_patrol")
        .params(Collections.singletonMap("target", "A101"))
        .callbackUrl("https://callback.example.com/openapi/task")
        .build());

type 和 messagesType 的取值范围以服务端 Open API 文档为准；params 的结构由具体指令类型决定，建议与对应指令定义保持一致。

7. 创建客户端

UTwinClient 是线程安全的入口对象，会复用 HTTP 连接池、Token 管理器和子客户端。

UTwinClient client = UTwinClient.builder()
    .endpoint("https://utwin.example.com")
    .credentialsProvider(EnvironmentCredentialsProvider.create())
    .build();

endpoint 填写 Open API 服务地址，不需要包含 /api/open/v1。SDK 会自动拼接 Open API 前缀。

8. CredentialsProvider

SDK 内置两种凭证提供者：

  • StaticCredentialsProvider：代码中显式传入固定 AccessKey 和 SecretKey。

  • EnvironmentCredentialsProvider：从 UTWIN_ACCESS_KEY 和 UTWIN_SECRET_KEY 读取。

凭证对象 AccessKeyCredentials 不可变，会在创建时校验空值。

9. HTTP 配置

HttpConfiguration 支持连接超时、读超时、最大连接数和代理配置。

HttpConfiguration httpConfiguration = HttpConfiguration.builder()
    .connectTimeout(Duration.ofSeconds(3))
    .socketTimeout(Duration.ofSeconds(10))
    .maxConnections(100)
    .defaultMaxPerRoute(20)
    .build();

UTwinClient client = UTwinClient.builder()
    .endpoint("https://utwin.example.com")
    .credentialsProvider(EnvironmentCredentialsProvider.create())
    .httpConfiguration(httpConfiguration)
    .build();

生产环境建议按应用并发量配置连接池上限，避免每次请求创建新客户端。

10. 重试策略

默认 maxRetries 为 0，不对 429、5xx 或 IOException 做业务重试。Token 过期导致的 401 会触发 Token 刷新并立即重试一次。

RetryPolicy retryPolicy = RetryPolicy.builder()
    .maxRetries(3)
    .build();

启用重试后，SDK 会对 429 使用 Retry-After 或默认等待时间，对 5xx 和网络异常使用指数退避。

11. Request 和 Response

每个接口都有独立的 Request 和 Response 类型。Request 使用 Builder 创建，构建后不可变；Response 由 Jackson 反序列化，未知字段会被忽略。

ListMapsRequest request = ListMapsRequest.builder()
    .pageNum(1)
    .pageSize(50)
    .search("展厅")
    .build();

ListMapsResponse response = client.map().listMaps(request);

接口返回业务失败时不会返回空 Response，而是抛出 ServiceException。

12. 分页

分页 Request 默认 pageNum=1、pageSize=20。分页接口同时提供手动分页和自动分页迭代器。

ListRobotsResponse page = client.robot().listRobots(
    ListRobotsRequest.builder().pageNum(1).pageSize(20).build());
for (RobotItem robot : client.robot()
        .listRobotsPaginator(ListRobotsRequest.builder().pageSize(50).build())
        .items()) {
    System.out.println(robot.id());
}

自动分页为惰性加载，迭代到下一页时才发起请求。

13. 错误处理

SDK 异常基类为 UTwinException：

  • ClientException：客户端侧问题，例如配置错误、网络异常、序列化失败。

  • ServiceException：Open API 返回业务失败，包含 errorCode、errorMessage 和 requestId。

try {
    client.robot().listRobots(ListRobotsRequest.builder().build());
} catch (ServiceException e) {
    log.warn("Open API failed, code={}, requestId={}",
        e.errorCode(), e.requestId());
} catch (ClientException e) {
    log.error("SDK client failed", e);
}

14. RobotClient

RobotClient 覆盖 5 个机器人接口：

  • listRobots / listRobotsPaginator：分页查询机器人。

  • getRobotRuntime：查询机器人运行数据。

  • sendCommand：下发任务指令。

  • getTaskResult：查询任务结果。

  • setCallback：设置数据订阅回调。

查询任务结果示例：

GetTaskResultResponse result = client.robot().getTaskResult(
    GetTaskResultRequest.builder()
        .robotId("robot-sn")
        .taskIds(Collections.singletonList("task-id"))
        .build());

15. WebSocket 实时数据通道

SDK 1.1.0 新增 WebSocket 实时数据通道，允许开发者订阅机器人 Topic 数据（速度、点云、相机帧、关节状态等），并接收 OpenAPI 任务结果的实时推送。

15.1. 前置条件

使用 WS 实时通道需要额外引入 utwin-opensdk-ws 模块：

<dependency>
    <groupId>com.bwton.utwin</groupId>
    <artifactId>utwin-opensdk-ws</artifactId>
    <version>${utwin-opensdk.version}</version>
</dependency>

15.2. 启用 WS 配置

构建 UTwinClient 时通过 wsConfiguration() 启用 WS 能力：

UTwinClient client = UTwinClient.builder()
    .endpoint("https://your-server.com")
    .credentialsProvider(StaticCredentialsProvider.create("accessKey", "secretKey"))
    .wsConfiguration(WsConfiguration.builder()
        .maxReconnectAttempts(5)        // 最大重连次数，默认 3
        .reconnectInterval(Duration.ofSeconds(10)) // 重连间隔，默认 5 秒
        .heartbeatInterval(Duration.ofSeconds(30))  // 心跳间隔，默认 30 秒
        .connectTimeout(Duration.ofSeconds(10))     // 连接超时，默认 10 秒
        .build())
    .build();

未配置 wsConfiguration 时，调用 robot().realtime(robotId) 将抛出 ClientException。

15.3. 建立连接

// 获取 RobotRealtimeClient（同一 robotId 返回同一实例）
RobotRealtimeClient realtime = client.robot().realtime("robot-uuid");

// 注册事件回调
realtime.onConnected(() -> System.out.println("已连接"));
realtime.onDisconnected(reason -> System.out.println("断开: " + reason));
realtime.onKicked(() -> System.out.println("被其他客户端挤占"));

// 同步阻塞连接（内部获取 WsToken → 建立 WS → 启动心跳）
realtime.connect();

connect() 是同步阻塞方法，成功返回后 WS 连接已建立。连接失败或超时会抛出 ClientException。

15.4. 订阅 Topic

// 使用 Topics 常量避免拼写错误
realtime.onTopic(Topics.CMD_VEL_ROBOT, data -> {
    System.out.println("速度数据: " + data.jsonData());
});

realtime.onTopic(Topics.CURRENT_POINTCLOUD, data -> {
    byte[] pointcloud = data.binaryData();
    // 处理点云二进制数据
});

realtime.onTopic(Topics.ROBOT_UPLOAD_INFO, data -> {
    System.out.println("机器人状态: " + data.jsonData());
});

// 也可以订阅自定义 Topic
realtime.onTopic("/custom/topic", data -> {
    // 处理自定义 Topic 数据
});

15.4.1. TopicData

每次推送通过 TopicData 传递，同时承载文本和二进制数据：

  • topic() — Topic 名称

  • jsonData() — JSON 文本数据（可能为 null）

  • binaryData() — 二进制数据（可能为 null）

  • hasJson() — jsonData 是否非空

  • hasBinary() — binaryData 是否非空

15.4.2. robot_upload_info 快照

订阅 robot_upload_info 后，SDK 自动维护最新快照。通过 getRobotInfo() 随时获取：

String info = realtime.getRobotInfo(); // 最近一次推送的 JSON，未收到时返回 null

15.4.3. 取消订阅

realtime.unsubscribe(Topics.CMD_VEL_ROBOT);

15.5. 任务结果推送

注册 onTaskResult 回调接收 OpenAPI 任务的实时状态推送：

realtime.onTaskResult(data -> {
    System.out.println("任务结果: " + data.jsonData());
});

// sendCommand 后 taskId 自动注册到 TaskCache
SendCommandResponse resp = client.robot().sendCommand(request);

15.5.1. TaskCache 本地缓存

TaskCache 提供 LRU + TTL 缓存，通过 WS 推送自动更新：

// 查询缓存中的任务结果
String result = realtime.taskCache().get(taskId);   // 缓存的 JSON，未命中返回 null
String status = realtime.taskCache().getStatus(taskId); // PENDING/EXECUTING/FINISHED/ERROR/TERMINATED

TaskCache 为最佳努力缓存，以 HTTP getTaskResult() 为权威。

15.6. 连接管理

15.6.1. 重连策略

网络异常或心跳超时时，SDK 自动在后台重连。重连流程：等待 reconnectInterval → 重新获取 WsToken → 重连 WS → 自动重订阅所有 Topic。

重连次数达到 maxReconnectAttempts 时停止，触发 onDisconnected(EXHAUSTED)。

15.6.2. 被挤占

服务端限制每个机器人只允许一个 OpenControl 连接。新连接建立时旧连接被挤占，收到 CLOSE_CONNECT 后触发 onKicked()，不触发自动重连。

15.6.3. 关闭连接

realtime.close();  // 关闭 WS、停止心跳、清理订阅
// 关闭后调用任何方法将抛出 IllegalStateException

// UTwinClient.close() 也会级联关闭所有 RobotRealtimeClient
client.close();

16. MapClient

地图领域入口为 client.map()，并提供二级子客户端：

  • client.map()：地图列表、版本、充电桩、导航点导出。

  • client.map().topoPath()：拓扑路径查询。

  • client.map().navPath()：导航路径查询。

  • client.map().narration()：讲解稿和讲解流程。

  • client.map().action()：动作列表和动作详情。

ListMapsResponse maps = client.map().listMaps(
    ListMapsRequest.builder().pageSize(20).build());

GetNavPathAllPathByEditionResponse paths = client.map().navPath()
    .getAllPathByEdition(GetNavPathAllPathByEditionRequest.builder()
        .editionId("edition-id")
        .build());

17. 性能建议

  • 复用 UTwinClient，不要为每次请求创建新客户端。

  • 对批量查询使用 SDK 提供的批量接口，例如地图版本批量查询。

  • 分页遍历时按应用处理能力设置 pageSize，避免单页过大导致服务和客户端内存压力。

  • 对幂等查询接口可启用 maxRetries，对可能触发业务副作用的操作谨慎启用重试。

  • 服务退出时调用 client.close() 释放连接池。

18. 日志

SDK 使用 SLF4J API，不绑定具体日志实现。应用可使用 Logback、Log4j2 或其他 SLF4J 兼容实现。

建议记录以下信息：

  • Open API 返回的 requestId。

  • ServiceException.errorCode 和 errorMessage。

  • 业务侧任务 ID、机器人 ID、地图版本 ID 等关联标识。

不要在日志中输出 SecretKey、Token 或完整签名参数。

19. 错误码

Open API 业务错误会映射为 ServiceException。常见类别：

  • 认证失败：AccessKey 不存在、签名错误、Token 过期。

  • 权限或状态错误：AccessKey 被禁用、机器人不可用、资源不存在。

  • 请求参数错误：必填字段缺失、指令参数格式不符合接口要求。

  • 限流：请求频率超过 Open API 限额。

完整错误码以交付给开发者的 Open API 错误码文档为准。

20. 对象速查

核心对象：

  • UTwinClient：SDK 入口。

  • AccessKeyCredentials：AccessKey/SecretKey 凭证。

  • TokenManager：Token 获取、缓存和刷新。

  • HttpConfiguration：HTTP 超时、连接池和代理配置。

  • RetryPolicy：重试次数和退避策略。

  • PageRequest / PageResponse：分页基础模型。

服务对象按领域分布在 com.bwton.utwin.opensdk.services.robot.model 和 com.bwton.utwin.opensdk.services.map.model 包下。

21. 指令速查

sendCommand 使用 SendCommandRequest 下发机器人指令：

  • robotId：机器人 SN 或 Open API 约定的机器人标识。

  • type：指令类型。

  • messagesType：消息类型。

  • params：指令参数对象。

  • callbackUrl：任务回调地址，可为空。

params 是开放对象，SDK 不在客户端强行收紧结构。新增或调整指令时，以交付给开发者的 Open API 文档和业务指令定义为准。

22. 枚举速查

SDK 当前以字符串或整数承载 Open API 枚举值，避免新增枚举时旧版 SDK 反序列化失败。

常见枚举包括：

  • 机器人指令 type。

  • 机器人指令 messagesType。

  • 地图、路径、动作和讲解资源状态。

新增枚举值通常按 PATCH 版本同步文档；如需要强类型枚举，将在后续 MINOR 版本中补充兼容封装。

23.2. WsConfiguration 参数

参数 默认值 说明

maxReconnectAttempts

3

最大重连次数，耗尽后停止重连

reconnectInterval

5 秒

重连间隔时长

30 秒

心跳发送间隔，连续 2 个心跳未收到 pong 判定超时

1000

taskCacheTtl

1 小时

TaskCache 条目存活时间

23.3. TaskCache 行为

  • sendCommand() 返回后自动注册 taskId（状态 PENDING），前提是 RobotRealtimeClient 已连接。

  • WS 推送 TASK_REPLY 时自动更新缓存（覆盖 jsonData 和 status）。

  • get(taskId) 返回缓存的 JSON 数据，未命中或已过期返回 null。

  • getStatus(taskId) 返回任务状态字符串。

  • TaskCache 为最佳努力缓存，以 HTTP getTaskResult() 为权威。

  • LRU 淘汰：条目数达到 taskCacheMaxSize 时淘汰最久未访问的条目。

  • TTL 过期：条目超过 taskCacheTtl 未被访问或更新时，get() 返回 null。

24. 兼容性和升级

SDK 使用语义化版本号：

  • PATCH：修复问题、完善文档或补充错误码说明。

  • MINOR：新增兼容能力，例如新增接口、可选参数或响应字段。

  • MAJOR：包含不兼容变更，例如方法签名调整、字段类型变化或接口移除。

升级 SDK 前建议先阅读随 SDK 交付的版本说明，重点关注以下内容：

  • 是否调整了最低 JDK 版本。

  • 是否新增或移除了依赖。

  • 是否有标记为废弃的接口需要迁移。

  • 是否存在 MAJOR 版本的不兼容变更。

默认情况下，SDK 的 JSON 反序列化会忽略未知字段。Open API 新增响应字段时，旧版 SDK 通常可以继续运行；应用只有在需要读取新字段或调用新接口时才需要升级 SDK。
